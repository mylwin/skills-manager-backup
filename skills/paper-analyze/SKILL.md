# 论文深度分析 Skill

对指定论文（arXiv ID、论文标题、URL 或本地 PDF）进行深度分析，生成一份内容全面、图文并茂的笔记。输出是**纯标准 Markdown**，不使用任何笔记软件专有语法，因此公式和图片可以在几乎任何 Markdown 渲染器中正常显示。

---

## 语言设置

通过 `--language zh` 或 `--language en` 指定输出语言，默认中文（`zh`）。如果没有显式指定，可根据用户当前对话使用的语言自动判断。语言设置贯穿全文（章节标题、正文内容需保持一致）。

---

## 输出位置

不再依赖任何 vault 路径或环境变量。默认输出到当前工作目录下的 `paper-notes/` 文件夹，用户可通过 `--output-dir` 自定义。

```
paper-notes/
└── [domain]/
    ├── [paper-title].md            # 笔记正文
    └── [paper-title]/
        └── images/
            ├── fig1.png
            ├── fig2.png
            └── ...
```

笔记与其 `images/` 文件夹应保持相对路径关系，这样整个 `[paper-title]/` 连同 `.md` 文件一起复制/分享到任何地方，图片依然能正常显示。

## 工作流程

### Step 0：初始化

```bash
mkdir -p /tmp/paper_analysis
cd /tmp/paper_analysis

OUTPUT_DIR="${OUTPUT_DIR:-./paper-notes}"   # 用户可通过 --output-dir 覆盖
mkdir -p "$OUTPUT_DIR"
```

### Step 1：识别论文

接受以下输入格式：
- arXiv ID：`2402.12345` 或 `arXiv:2402.12345`
- 论文标题（用于搜索）
- 论文 URL（arXiv / OpenReview / Hugging Face Papers 等）
- 本地 PDF 文件路径（用户已上传）

**检查是否已分析过**：在 `$OUTPUT_DIR` 下按 arXiv ID 或标题搜索已有笔记，若找到则直接读取返回，避免重复分析（除非用户要求重新分析）。

### Step 2：获取论文内容

**2.1 元数据**

优先使用 arXiv API 获取结构化元数据：

```
GET http://export.arxiv.org/api/query?id_list=[PAPER_ID]
```

提取：标题、作者、摘要、发布日期、分类（categories）、链接。

**2.2 PDF 正文**

- 如果用户已上传 PDF，直接使用（参考 `pdf-reading` skill 提取文本/结构）。
- 否则下载：

```bash
curl -L "https://arxiv.org/pdf/[PAPER_ID]" -o /tmp/paper_analysis/[PAPER_ID].pdf
```

**2.3 提取图片（用于图文并茂）**

使用 `pdf` / `pdf-reading` skill 从 PDF 中提取插图（架构图、方法图、实验结果图等），保存为标准图片格式：

```bash
# 示例：将图片保存到笔记对应的 images 目录
NOTE_IMAGES_DIR="$OUTPUT_DIR/[domain]/[paper-title]/images"
mkdir -p "$NOTE_IMAGES_DIR"
# 提取出的图片统一重命名为 fig1.png, fig2.png, ... 并保存到此目录
```

命名规则：`fig1.png`、`fig2.png`……按论文中出现顺序编号，便于在正文中引用。

**2.4（可选）源码包**

如果需要更精确的正文内容（而不仅是 PDF 提取文本），可选下载 e-print 源码：

```bash
curl -L "https://arxiv.org/e-print/[PAPER_ID]" -o /tmp/paper_analysis/[PAPER_ID].tar.gz
tar -xzf /tmp/paper_analysis/[PAPER_ID].tar.gz -C /tmp/paper_analysis/
```

这一步是加分项，不是必须的——PDF 提取的文本通常已经足够支撑深度分析。

### Step 3：深度分析

对论文进行全面分析，覆盖以下维度（保持人类可读、逻辑清晰，避免空洞的模板化语言）：

1. **摘要与翻译**：原文摘要 + 准确流畅的中文翻译（如果 language=zh）+ 核心要点提炼
2. **研究背景与动机**：领域现状、现有方法局限性、为什么需要这项研究
3. **方法论**：核心思想（用通俗语言先讲一遍）→ 方法框架 → 各模块细节 → 关键创新点
4. **实验结果**：数据集、基线方法、评估指标、主要结果（用表格呈现）、消融实验
5. **深度分析**：理论贡献、实际应用价值、优势、局限性、适用/不适用场景
6. **与相关工作对比**：搜索并对比 2-3 篇密切相关的论文，说明改进/扩展/对比关系
7. **技术路线定位**：本文属于哪个技术脉络，在其中处于什么位置
8. **未来工作与改进建议**
9. **综合评价**：分维度打分（0-10），见下方评分标准

### Step 4：公式与图片渲染规范（关键）

这是本 skill 相比通用写作最重要的约束，确保笔记在任何标准 Markdown 环境中都能正确渲染。
**本节全部规则对"直接输出给用户的聊天回复"（如 Step 6 的分析摘要、任何含公式的解释文字）
同等强制**——用户在渲染后的界面里阅读回复，公式写法不合规同样会显示成乱码；
发送前与写笔记一样先自查一遍：

**公式**
- 行内公式：`$...$`，例如：模型目标是最小化 $L(\theta)$。**禁止使用 `\( ... \)` 定界符**，
  禁止用反引号把公式包成代码，也不要裸写 Unicode 数学符号（如 ‖∇f(x)‖、η_t）充当公式。
- 行内公式细则（Typora 等渲染器的硬性要求，违反任何一条都会渲染失败）：
  - `$` 与公式内容之间**不留空格**（写 `$x_t$`，不要写 `$ x_t $`）；
  - 行内公式与前后的中文字符/中文标点之间**各留一个半角空格**（"其中 $\eta_t$ 是学习率" ✅ / "其中$\eta_t$是学习率" ❌）；
  - `$...$` 必须在同一行内闭合，不要跨行书写；
  - 表格单元格内的公式禁止出现裸 `|` 字符（会被当成列分隔符），条件符号用 `\mid`，范数一律写 `\Vert x \Vert`。
- 块级公式：`$$...$$`，且**独立成行，前后各空一行**（提升在 GitHub / VS Code / Typora 等不同解析器下的兼容性）：

  ```
  损失函数定义为：

  $$
  \theta^* = \arg\min_\theta L(\theta)
  $$

  其中 ...
  ```
- 公式编号不用 `\tag{}`，改在正文文字里标注（如 "即论文中的式 (4)："）。
- 命令只用基础子集：`\frac`、`\sqrt`、`\nabla`、`\mathbb`、`\mathcal`、上下标（多字符下标必须加花括号，如 `x_{t+1}`）、
  希腊字母、`\le`/`\ge`、`\min`/`\max`、`\sum`、`\arg`、`\propto`、`\Rightarrow`、`\left( \right)`、`\Vert`、`\mid`、`\cdot`、`\top`。
- **禁止**使用以下易导致整段渲染成乱码的命令：`\tag{n}`、`\big`/`\Big`/`\bigl` 系列、`\lesssim`、
  `\;` `\,` `\!` `\quad` 等间距命令、`\boxed`、`\underbrace`/`\overbrace`、`\overset`/`\underset`、
  `\|`（必须换成 `\Vert`）、`\text{}` 里嵌中文（公式内需要文字说明时，把文字挪到公式外的正文里）。
- **禁止**用三个反引号代码块包裹需要渲染的公式（那样只会显示成代码而不是公式）。
- **禁止**用纯文本伪公式（如 `theta* = argmin_theta L(theta)`）代替 LaTeX。
- 符号**含义**尽量与原论文保持一致，但**书写命令**必须按上述白名单转换（例如原文的 `\|` 改写成 `\Vert`、去掉 `\tag{}`）。
- 写入笔记前逐条自查：行内定界符是否为 `$...$`、`$` 内侧是否贴了空格、与中文之间是否留了空格、
  `$...$` 是否同行闭合、是否混入禁用命令、表格单元格内是否有裸 `|`。

**图片**
- 一律使用标准 Markdown 图片语法：`![图注](images/fig1.png)`。
- 路径使用**相对路径**（相对于笔记 `.md` 文件），不要用绝对路径，不要用 `![[filename|800]]` 这类笔记软件专有 wikilink 语法。
- 每张图配一句简短说明其含义：

  ```markdown
  ![图1：整体架构，输入经过编码器后...](images/fig1.png)

  > 图1：[对图中各部分含义及关系的说明]
  ```

**架构图（当论文没有合适的现成图时）**
- 优先使用论文原图。
- 论文确实没有可用架构图时，用 **Mermaid** 代码块画流程图/架构图——GitHub、VS Code、Typora、大多数 Markdown 预览工具都原生支持渲染：

  ```mermaid
  flowchart LR
      A[输入] --> B[模块1]
      B --> C[模块2]
      C --> D[输出]
  ```
- 不再使用 ASCII 手绘图或任何笔记软件的 Canvas 功能作为架构图的备选方案。

**内部引用/相关论文**
- 不使用 `[[wikilink]]` 语法。
- 如果相关论文也生成了本地笔记，用标准 Markdown 相对链接：`[论文标题](../其他领域/其他论文.md)`。
- 如果没有对应的本地笔记，直接用加粗文字标出标题即可：`**相关论文标题**（作者, 年份）`。

**提示/警告**
- 不使用 `> [!tip]` 这类笔记软件专有的 callout 语法（很多 Markdown 渲染器不支持，会原样显示成文字）。
- 用标准引用块 + 加粗代替：

  ```markdown
  > **关键启示：** 论文最重要的启示，一句话总结核心思想。

  > **注意事项：**
  > - 事项1
  > - 事项2
  ```

**Frontmatter（可选）**
- 如果需要程序化处理（检索、去重），可以保留一段简单的 YAML frontmatter，但这只是普通元数据，不依赖任何特定软件解析规则。字符串统一加双引号即可，没有额外的转义要求。

### Step 5：生成笔记

```bash
python3 scripts/generate_note.py \
  --paper-id "[PAPER_ID]" \
  --title "[标题]" \
  --authors "[作者]" \
  --domain "[领域]" \
  --output-dir "$OUTPUT_DIR" \
  --language "$LANGUAGE"
```

脚本会生成带占位符的标准 Markdown 骨架，之后需要把分析内容逐节填入，并将 Step 2.3 提取的图片路径正确插入到对应小节。

**领域推断规则（用于分目录整理，纯本地文件夹分类，无特殊含义）**：
- 提到 agent / swarm / multi-agent / orchestration → `Agent`
- 提到 vision / visual / image / video → `Multimodal`
- 提到 reinforcement learning / RL → `RL`
- 提到 language model / LLM / MoE → `LLM`
- 否则 → `Other`

### Step 6：输出分析摘要

分析完成后，向用户展示简要摘要（评分、亮点、优劣势、相关论文、笔记文件路径），并提示笔记文件已生成在 `$OUTPUT_DIR` 下，可以直接下载 / 用任意 Markdown 工具打开。

## 评分标准（0-10 分制）

**创新性**
- 9-10：新颖突破、新范式
- 7-8：显著改进或有价值的新组合
- 5-6：次要贡献，思路已知
- 3-4：增量式改进
- 1-2：几乎没有新意

**技术质量**
- 9-10：方法论严谨、设计合理
- 7-8：方法良好，存在次要问题
- 5-6：方法可接受，存在一些问题
- 3-4：方法存在明显问题
- 1-2：方法有严重缺陷

**实验充分性**
- 9-10：实验全面、基线强
- 7-8：实验良好、基线充分
- 5-6：实验可接受、基线部分覆盖
- 3-4：实验有限、基线较弱
- 1-2：实验不足或缺少基线

**写作质量**
- 9-10：清晰、组织良好
- 7-8：整体清晰，个别问题
- 5-6：可理解，部分表述不清
- 3-4：较难理解
- 1-2：写作质量差

**实用性**
- 9-10：实用价值高，可直接落地
- 7-8：实用潜力良好
- 5-6：中等实用价值
- 3-4：实用性有限，偏理论
- 1-2：实用性很低

## 重要规则

- **只输出标准 Markdown**：不使用任何笔记软件专有语法（wikilink、canvas、admonition callout 等），确保笔记可以脱离特定软件独立打开、分享、渲染。
- **图片必须能独立渲染**：使用相对路径的标准 `![]()` 语法，笔记文件与 `images/` 文件夹一起移动/分享时图片依然可见。
- **公式必须能独立渲染**：统一使用 `$...$` / `$$...$$`，不要用代码块包裹、不要用伪公式代替；
  行内公式 `$` 内侧不留空格、与中文之间各留一个半角空格，命令严格遵守 Step 4 的白名单/黑名单。
- **保留用户已有笔记**：如果目标路径已有手动编辑过的笔记，不要覆盖，除非用户明确要求重新分析。
- **图文并茂**：论文中的核心图（架构图、方法图、关键实验图）都应提取并插入到笔记对应位置。
- **根据 `--language` 选择输出语言**：章节标题和正文都要保持语言一致。
- **优雅处理错误**：某一个信息来源失败（如源码包下载失败）不应中断整个分析，在笔记中如实注明该处信息不可得即可。

## 错误处理

- **论文未找到**：检查 ID/标题格式是否正确，提示用户换个关键词搜索。
- **arXiv 无法访问**：如实在笔记中注明该来源不可用，尽量用已有信息（如用户上传的 PDF）继续分析。
- **PDF 图片提取失败**：退化为仅描述图片内容（文字说明），并在笔记中注明"原图提取失败"。
- **相关论文检索不到**：如实说明缺乏对比语境，不要编造论文。

## 使用说明

当用户要求分析某篇论文时（给出 arXiv ID / 标题 / URL / 本地 PDF）：

1. 按 Step 0-2 获取论文内容与图片
2. 按 Step 3 完成深度分析
3. 严格遵守 Step 4 的公式/图片渲染规范
4. 调用 `scripts/generate_note.py` 生成笔记骨架，并把分析内容填入
5. 把最终笔记（连同 `images/` 文件夹）交付给用户
